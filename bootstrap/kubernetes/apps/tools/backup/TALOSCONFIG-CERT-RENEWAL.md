# Renewing the `talosconfig` client certificate

## What happened (2026-08-29)

The `os:admin` client certificate embedded in the `talosconfig` Secret
(namespace `backup-system`, used by the `etcd-backup` CronJob to take etcd
snapshots via `talosctl`) expired on **2026-08-28 23:48 GMT**. Certificates
generated by `talosctl gen config` / `talosctl config new` default to **1
year of validity** (`--crt-ttl`, default `8760h`), and Talos does not rotate
them on its own — it's a static credential that has to be renewed by hand.

Symptom: the `etcd-backup` CronJob started failing every night with:

```
error reading file: rpc error: code = Unavailable desc = connection error:
desc = "error reading server preface: remote error: tls: expired certificate"
```

This also blocks any other use of `talosctl` against the cluster with that
same identity (e.g. an emergency recovery).

The cluster CA (`cluster.ca`) itself is still valid until 2035 — only the
*client* certificate expires, not the CA.

## How to renew it

You'll need `talosctl` installed locally and one of the `controlplane-N.yaml`
files from the `talos-config` repo (it has the cluster CA's private key
embedded, so that alone is enough — no need for an already-valid
`talosconfig`).

### 1. Extract a secrets bundle from an existing controlplane.yaml

```bash
talosctl gen secrets \
  --from-controlplane-config /path/to/talos-config/controlplane-1.yaml \
  -o /tmp/secrets.yaml --force
```

### 2. Generate a new talosconfig from that bundle

```bash
talosctl gen config synergia-k8s https://10.42.20.4:6443 \
  --with-secrets /tmp/secrets.yaml \
  -t talosconfig \
  -o /tmp/talosconfig-new --force
```

Confirm the expiration date is in the future:

```bash
TALOSCONFIG=/tmp/talosconfig-new talosctl config info
```

### 3. (Optional) Request a longer-lived cert using the new talosconfig

If you want more than 1 year of validity, use the freshly generated
talosconfig (already valid) to request a new one with a different TTL — no
need to repeat steps 1-2 for this:

```bash
TALOSCONFIG=/tmp/talosconfig-new talosctl config new /tmp/talosconfig-Nyears \
  -e 10.42.20.4 -n 10.42.20.5 \
  --crt-ttl 87600h \
  --roles os:admin
# 87600h = 10 years. Adjust as needed.
```

### 4. Update the SOPS-encrypted Secret in the repo

The `secret-talosconfig.yaml` Secret (`bootstrap/kubernetes/apps/secrets/`)
has a `stringData.config` key holding the full talosconfig content as a YAML
block. Replace that block with the content of `/tmp/talosconfig-new` (or
whichever file was generated in step 3) and re-encrypt:

```bash
cd synergia-k8s

python3 <<'PYEOF'
import subprocess

decrypted = subprocess.run(
    ["sops", "-d", "bootstrap/kubernetes/apps/secrets/secret-talosconfig.yaml"],
    capture_output=True, text=True, check=True
).stdout

with open("/tmp/talosconfig-new") as f:
    new_config = f.read()

lines = decrypted.splitlines()
out = []
i = 0
replaced = False
while i < len(lines):
    line = lines[i]
    out.append(line)
    if line.strip() == "config: |":
        replaced = True
        indent = " " * (len(line) - len(line.lstrip()) + 4)
        for cfg_line in new_config.splitlines():
            out.append(indent + cfg_line if cfg_line else "")
        i += 1
        base_indent = len(line) - len(line.lstrip())
        while i < len(lines) and (lines[i].strip() == "" or (len(lines[i]) - len(lines[i].lstrip())) > base_indent):
            i += 1
        continue
    i += 1

assert replaced, "config block not found!"
with open("bootstrap/kubernetes/apps/secrets/secret-talosconfig.yaml", "w") as f:
    f.write("\n".join(out) + "\n")
PYEOF

sops -e -i bootstrap/kubernetes/apps/secrets/secret-talosconfig.yaml

# Verify without ever printing the private key:
sops -d bootstrap/kubernetes/apps/secrets/secret-talosconfig.yaml \
  | grep "crt:" | awk '{print $2}' | base64 -d | openssl x509 -noout -dates
```

### 5. Commit, push, and force Flux to reconcile

```bash
git add bootstrap/kubernetes/apps/secrets/secret-talosconfig.yaml
git commit -m "[backup] renew talosconfig client cert"
git push origin main
```

If Flux is slow to pick it up, force-reconcile the `GitRepository` and the
`apps-secrets-config` `Kustomization` via the
`reconcile.fluxcd.io/requestedAt` annotation, or just wait for the 5-minute
interval.

### 6. Verify the real backup works

Run a manual Job instead of waiting for the next 3am run:

```bash
kubectl create job etcd-backup-verify -n backup-system --from=cronjob/etcd-backup
kubectl logs -f -n backup-system job/etcd-backup-verify
kubectl delete job etcd-backup-verify -n backup-system
```

### 7. Clean up

Delete the local temporary files — `/tmp/secrets.yaml` in particular holds
the full cluster CA private key:

```bash
rm -f /tmp/secrets.yaml /tmp/talosconfig-new /tmp/talosconfig-Nyears
```

## Automatic reminder

To avoid repeating this incident, a CronJob (`talosconfig-cert-check`,
namespace `backup-system`, runs daily) computes the days remaining on the
certificate and pushes the `talos_client_cert_expiry_days` metric to a
Prometheus Pushgateway. An alert (`TalosConfigCertExpiringSoon`, defined in
`bootstrap/kubernetes/apps/monitoring/prometheus/app/configmap-prometheus.yaml`)
fires via Telegram (same receiver already used for every other alert in this
cluster) once fewer than 7 days remain.

See `bootstrap/kubernetes/apps/tools/backup/app/talosconfig-cert-check.yaml`.
